## Перенесённая логика и адаптация

- Один HTMLAudioElement, один AudioContext/MediaElementSource/Analyser для desktop; прямой native media путь для Android/iOS/touch. Подключение графа выполняется только после возобновления контекста. Нет периодического выдуманного нормализатора или синтетического спектра.
- Отдельный AbortController и номер поколения для запуска; отменяемое ожидание индекса/Piper/play; завершение попытки ровно один раз. Запоздалые события и промисы не очищают новую сессию. Номер отдельной попытки защищает и запоздалый resume при переходе к резерву.
- Очередь диалога ждёт `ended` каждой реплики. Stop отменяет ожидание и продолжение очереди, старая очередь не снимает состояние новой.
- Watchdog продлевается реальным timeupdate. Пауза останавливает watchdog; длительная пауза не включает резерв. Скорость MP3 и громкость меняются без перезапуска. Системному TTS для применения новой скорости нужен повтор — сообщение об этом остаётся явным.
- Готовый румынский MP3 → румынский Piper endpoint/его кеш → настоящий ro-RO/ro → понятная ошибка. Русские, английские, болгарские и ro-MD голоса не подставляются. Диагностический режим `file` намеренно проверяет только MP3.
- Piper проверяется по JSON health `language=ro-RO`, `voice=Piper/Mihai`; ответ должен быть аудио с `X-Speech-Language: ro-RO`. Blob воспроизводится из единственного ответа, освобождается после завершения и может сохраняться для офлайн-повтора, максимум 256 записей.
- Индекс разделён на 256 адресуемых по FNV-префиксу частей, LRU разобранных частей ограничен восемью. На главной нет запроса полного индекса; небольшой bootstrap покрывает 80 исходных текстов. Максимальная часть — 8067 байт. Service worker кеширует до 32 частей по запросу, не предзагружая весь индекс.
- Румынская нормализация сохраняет диакритику и пунктуацию. NFC, регистр и пробелы нормализуются; ă/â/î/ș/ț, ş/ș и ţ/ț не смешиваются. Полный ключ текста хранится внутри части: совпадение FNV-префикса не означает совпадения слова. Точные ключи сохраняются отдельно. Все 11 455 текстов проверены против готовых файлов; неоднозначных нормализованных ключей нет.

## AbortError и жизненный цикл

Пользовательский лог `The play() request was interrupted because the media was removed from the document` подтверждает прерывание жизненного цикла медиаплеера. Для `cafea` сервер выдаёт настоящий MP3: `/audio/2b74797589c1dd08c06b07cb.mp3`, HTTP 206, `audio/mpeg`, 4431 байт. Это не обнаруженная ошибка 404.

Долгоживущий плеер закреплён в `document.body` вне React root до play(). Смена карточки, рендер и закрытие модалки не удаляют его. Адаптация stopSpeech сохраняет элемент и src: сброс ресурса через removeAttribute/load из образца не переносился. Глобальные stopAudio из cleanup экранов/модалок убраны. Отмена пользовательскими кнопками остаётся явной. Для владельцев асинхронных проверок есть `stopAudioIfSession`, который не останавливает чужую новую сессию.

Точный момент удаления элемента в браузере пользователя агент не наблюдал. Нельзя объявлять конкретный триггер подтверждённым исключительно по анализу кода. Наблюдаемый тип сбоя закрыт регрессионными тестами DOM/React и защитой сессий; настоящая браузерная проверка ещё нужна.

## cafea, браузер и Vercel

Готовый cafea MP3, его индекс и HTTP-выдача проверены. В тесте он запускается через единый connected-плеер. **Реальное нажатие cafea в браузере, продвижение native currentTime, завершение и слышимость агентом не подтверждены.** Browser вернул `No browser is available`. Физического прослушивания не было.

В настройках добавлена проверка **33 MP3**: cafea и ещё 19 карточек, 10 предложений, 3 полных диалога. Она сохраняет HTTP, playing/ended, число timeupdate, currentTime/duration и ошибки. Проверка запускается только кнопкой; JSON можно скачать. Это инструмент для получения недостающего браузерного свидетельства, а не заранее заполненный успешный отчёт.

Код опубликован на Vercel из коммита `c16ad12`. Все 1283 HTTP-проверки прошли, ошибок нет: 256 частей индекса, 994 варианта фото и 33 MP3. Основной JS — 453 095 байт, 83 уникальные ссылки MP3; полный индекс отсутствует, плеер и кеш частей присутствуют. Результаты: `quality/audio-port-http-vercel.json`. `/api/tts/health` на статическом Vercel возвращает 404; динамический Piper там не размещён. На статическом Vercel работают готовые MP3; Python там не запускается. Для динамической генерации нужен отдельно размещённый endpoint, заданный `VITE_ROMANA_TTS_ENDPOINT`. На рабочем компьютере существующее Python-окружение и модель подключены через игнорируемый `.env.local`.

Остаются непроверенными реальный звук/AbortError на устройстве пользователя, native мобильное воспроизведение, WebAudio на настоящем desktop, PWA в авиарежиме и визуальное отображение srcset. Эти ограничения не подменяются успешной сборкой или HTTP-проверками.
