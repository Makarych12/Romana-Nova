# ROMÂNA NOVA — ревизия медиа от 18 октября 2026

## Статус

Исправления кода и данных подготовлены, но **реальное воспроизведение из интерфейса браузера не подтверждено**. Плагин браузера дважды сообщил `No browser is available`; список доступных браузеров пуст. Физически прослушать звук в этой сессии невозможно. Успешная сборка и декодирование MP3 не заменяют такую проверку.

## 1. Почему не работало аудио

Подтверждённый дефект данных: 400 уникальных примеров из опубликованного словаря отсутствовали в аудиоманифесте. Например, `Vântul a lovit ferestrele cu forță.`. При отсутствии румынского системного голоса эти кнопки не могли произнести фразы.

У всех 7984 заголовков слов локальные MP3 были привязаны ещё до ревизии. Все исходные 10 916 MP3 декодируются. Контрольные слово, пример и диалог на Vercel возвращали HTTP 206 с Content-Type `audio/mpeg`. Поэтому утверждать, что причиной отсутствия **всего** звука были неподключённые MP3, неверно. Причина отказа на конкретном устройстве пользователя пока не воспроизведена.

Подтверждённый недостаток логики офлайн-кеширования: Workbox сохранял только ответы 200, а медиаплеер может получать 206 по Range-запросу. Само проигрывание поэтому не гарантировало появления полного файла в офлайн-кеше. Теперь после события `playing` идёт отдельный полный запрос без Range; он не задерживает запуск по нажатию. Кеш v2 принимает только полные `audio/mpeg`. Работу этого механизма в реальном service worker ещё нужно проверить браузером.

Также локальный MP3 больше не зависит от успешного вызова системного SpeechSynthesis.cancel/getVoices. Уведомления об ошибках содержат MediaError/исключение и путь файла. Это защитные исправления, а не доказанная причина отказа на устройстве пользователя.

## 2. Изменённый код

- `src/lib/audio.ts`: общий движок слов, примеров, уроков, диалогов и упражнений; уточнены ошибки, URL источника, независимость MP3 от отказа системного голоса.
- `src/lib/audio-cache.ts`: полный запрос MP3 для Workbox после начала воспроизведения.
- `src/lib/media-check.ts`: HTTP-код, MIME и URL при ошибке; отмена и таймаут диагностики.
- `src/components/AudioControls.tsx`, `src/components/Dictionary.tsx`: кнопка «Проверить звук» с непосредственным запуском MP3 и отдельной проверкой выдачи; счётчик фотографий.
- `src/components/AppUpdate.tsx`, `src/App.tsx`, `src/pwa.d.ts`: обновление PWA по кнопке после сохранения прогресса.
- `src/components/SafeImage.tsx`: ошибка предыдущего изображения больше не скрывает новое при смене src.
- `src/styles.css`: оформление результата проверки звука в существующей палитре.
- `vite.config.ts`: регистрация PWA из приложения, clientsClaim и кеш MP3 v2 с MIME-проверкой и RangeRequestsPlugin.
- `scripts/prepare-content.mjs`: сохранение старых каталогов для старых PWA; текущий каталог исключён из списка резервных версий.
- `scripts/audit-media.mjs`: воспроизводимая ревизия привязок, сигнатур, сохранности исходных файлов и полного декодирования FFmpeg.

Изменены также аудиоманифест, источники аудио, каталог, привязки фото, журнал визуальной проверки и редакторские дополнения примеров. Новых библиотек нет. Использованы установленные Piper, ONNX Runtime, FFmpeg и Pillow. Румынская модель Mihai отсутствовала локально и была загружена во временную папку для подготовки недостающих MP3; она не включена в сайт.

## Дополнение: AbortError на cafea

Пользователь сообщил реальную ошибку браузера для `/audio/2b74797589c1dd08c06b07cb.mp3`: `The play() request was interrupted because the media was removed from the document`. Это подтверждает прерывание запуска медиаплеера, но не успешную слышимость. Прямой Range-запрос к этому файлу на Vercel возвращает HTTP 206, `audio/mpeg`, полный размер 4431 байт.

Ранее движок создавал новый отсоединённый `Audio` при каждом запуске, а очистка делала `pause()`, удаляла `src` и вызывала `load()`. Теперь один постоянный `<audio id="romana-audio-player">` присоединён к `document.body` вне React root **до** `play()`, сохраняется между карточками и при остановке. Остановка ставит на паузу и отвязывает обработчики, не удаляя элемент, `src` или ресурс через `load()`. При выборе другой фразы источник меняется под новым номером запуска; запоздалые отказы старого play игнорируются.

Добавлены регрессионные проверки: проигрывание требует connected-элемент; смена содержимого React root и карточки сохраняет один плеер; stop не удаляет элемент и не вызывает load/removeAttribute; AbortError старого play не портит новый запуск. Это автоматические тесты с моделью HTMLMediaElement, **не воспроизведение в настоящем Chrome**. Текст ошибки соответствует описанному Chrome классу прерываний: https://developer.chrome.com/blog/play-request-was-interrupted . Точный триггер удаления в браузере пользователя не наблюдался; исправление устраняет отсоединённый элемент и лишний сброс ресурса.

После исправления проходят 84 автоматических теста, включая проверку того, что актуальный AbortError остаётся видимой ошибкой. При повторном AbortError диагностика дополнительно показывает isConnected, readyState, networkState и видимость страницы.

Браузерный плагин при повторной попытке всё ещё отвечает `No browser is available`. После публикации требуется повторная проверка кнопок `cafea` и «Проверить звук» на устройстве пользователя. Объявлять слышимость подтверждённой пока нельзя.
